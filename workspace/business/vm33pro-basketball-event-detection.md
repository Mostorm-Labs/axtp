# VM33PRO 篮球投篮与进球事件检测需求

## 状态

- 阶段：Stage 00 Business Intake
- 状态：draft，待产品、算法、固件和 App 评审
- 来源：产品口头需求（2026-08-07）
- 适用产品：VM33PRO

## 背景

VM33PRO 设备计划服务篮球投篮场景。设备侧的检测算法能够识别用户的投篮行为，并进一步判断是否进球；App 需要通过 WebSocket 接收设备主动下发的事件，用于实时展示、计数或后续业务记录。App 还需要提供一个开关，控制设备是否开启篮球事件检测。

本文件只记录业务意图、范围、责任和待确认事项，不是 AXTP 的实现合同。具体 method、event、schema、错误码、能力名、字段 ID 和线上的消息格式，需要在后续 flow / protocol 阶段确认。

## 业务目标

- 让用户在 App 中明确控制 VM33PRO 是否启用篮球事件检测。
- 检测开启后，设备在篮球场景中识别投篮事件，并在满足条件时识别进球事件。
- 设备将识别结果以近实时事件通知的方式发送到 App，App 可以据此更新当前回合、命中数或其他产品展示。
- 检测关闭、设备不可用或连接异常时，App 能向用户展示清晰且可恢复的状态。

## 目标用户与参与方

| 参与方 | 目标 / 责任 |
|---|---|
| 用户 / 篮球训练者 | 在 App 中开启或关闭检测，并查看投篮、进球结果。 |

| VM33PRO 固件 | 保存或应用检测开关状态；管理 WebSocket 会话；在检测开启且设备条件满足时向 App 推送事件；报告不可用或失败状态。 |
| 篮球事件检测算法 | 识别投篮尝试与进球结果，提供算法状态、置信度或诊断信息（具体是否对 App 可见待确认）。 |
| SDK / WebSocket 适配层 | 将设备连接、认证、消息分发和重连能力提供给 App（是否存在独立 SDK 待确认）。 |
| 云端 / 网关（如有） | 仅在实际链路包含云端转发时参与；当前需求未说明，不能默认其承担事件存储或转发。 |

## 范围

本需求包含：

- VM33PRO 篮球事件检测能力的启用、停用和当前状态展示。
- 投篮事件的设备侧识别与 App 侧接收。
- 进球事件的设备侧识别与 App 侧接收。
- 检测开关变化、算法不可用、设备忙、权限不足或连接异常时的状态反馈。
- WebSocket 建立、断开、重连期间的事件接收体验和状态恢复策略。
- 事件在 App 中的实时展示、计数或记录所需的业务语义（不在此阶段定义具体数据字段）。

## 非目标

- 不定义篮球检测算法的模型、训练数据、摄像头安装角度、球场标定或硬件实现。
- 不定义“投篮”和“进球”的最终判定阈值、置信度算法或误检率指标；这些需要算法和产品共同确认。
- 不在本阶段定义 AXTP 的具体 method / event / schema / error / capability 名称、ID、字段或 JSON 示例。
- 不覆盖视频预览、视频流传输、录像、球员身份识别、比分系统或训练报告，除非后续产品范围明确纳入。
- 不修改旧 VM33 HTTP JSON 协议及其兼容迁移产物。

## 主场景

1. 用户打开 App 的篮球检测设置或训练页面。
2. App 获取并展示 VM33PRO 当前篮球事件检测状态；如果设备不支持或算法不可用，App 展示不可用原因。
3. 用户打开检测开关，App 将控制请求发送到设备。
4. 设备校验当前运行条件并应用开关，向 App 返回已生效、处理中或失败的状态。
5. 检测处于开启且场景满足算法要求时，设备识别投篮动作并向 App 推送投篮事件。
6. 当设备判断该次投篮命中时，向 App 推送进球事件；App 更新实时展示或统计。
7. 用户关闭检测开关，设备停止产生新的篮球检测事件，并向 App 确认最终状态。

## 交互与异常场景

- **设备重启或重新连接**：App 需要重新获取检测开关的有效状态；是否自动恢复上次状态、恢复默认关闭，还是由设备策略决定，需要确认。
- **WebSocket 断线后重连**：App 需要知道检测是否仍然开启，并按产品策略处理断线期间的事件（丢弃、补发、重新同步或仅接收重连后的新事件）。
- **重复或乱序事件**：App 不能因重连、重试或设备重复发送而重复计数；事件去重和顺序依据需要定义。
- **算法暂不可用**：例如摄像头被占用、隐私遮挡、场景未准备好、标定缺失或光照不满足条件时，App 展示不可用/暂停状态，恢复后是否自动继续需要确认。
- **开关控制失败**：设备拒绝、超时或参数不合法时，App 不应把 UI 显示为已生效，并提供重试或恢复操作。
- **检测过程中关闭开关**：正在处理的投篮是否允许完成并发送结果，还是立即停止全部事件，需要确认。
- **事件判定不确定**：低置信度或无法确定是否进球时，设备是否发送待确认/未知结果，或只发送投篮事件，需要确认。

## 产品约束与非功能要求

- **近实时性**：事件从设备判定到 App 可见应满足训练场景的近实时体验；目标时延和验收测量方法待确认。
- **一致性**：App 展示的开关状态必须代表设备实际生效状态，而不是仅代表本地点击结果。
- **可观测性**：至少能区分检测关闭、检测开启、检测处理中、算法不可用、连接中断和控制失败等用户可理解状态。
- **可靠性**：事件推送需要有明确的会话生命周期、重连和错误恢复策略；是否要求离线缓存或补发待确认。
- **顺序与关联**：需要明确投篮与进球的关联关系、事件产生时间、设备时间与 App 接收时间，以及是否允许一个投篮对应多个状态变化。
- **去重**：App 或 SDK 需要具备可执行的去重依据，避免重复连接或重试导致重复统计。
- **权限与安全**：只有已授权的 App 会话才能控制开关或接收事件；现有 WebSocket 认证、连接方向和会话权限模型需复用或补充确认。
- **兼容性**：旧 VM33 设备继续走旧协议；VM33PRO 新业务按 AXTP 新协议演进，App 应基于设备能力或版本做兼容分支。
- **性能与带宽**：事件消息应适配 WebSocket 链路和设备资源；事件频率上限、消息大小和高频场景下的降级策略待确认。
- **隐私**：篮球事件是否允许上传云端、是否需要用户同意、是否保存原始视频或仅保存事件摘要，待产品和隐私评审。

## 设备、App、云端与运行时职责

### VM33PRO 设备 / 固件

- 提供篮球检测开关的读取、应用和生效状态。
- 根据设备能力和运行条件启动或停止检测算法。
- 将投篮与进球结果以设备主动事件通知方式发送给已授权的 App 会话。
- 在算法不可用、设备忙、摄像头冲突或内部错误时提供可诊断状态。
- 明确重启、断线、升级和恢复默认后的开关初始值及事件行为。

### App / SDK

- 展示当前有效状态，区分用户期望状态与设备实际状态（如存在异步生效）。
- 发送开关控制并处理成功、失败、超时和重连。
- 接收、校验、去重并按顺序处理投篮与进球事件。
- 根据事件更新实时 UI、训练计数或本地记录；在断线时向用户提示数据完整性影响。
- 根据设备能力选择是否展示篮球检测入口，避免对不支持的设备发送无效控制。

### 云端 / 网关（如纳入链路）

- 明确是否只做 WebSocket 转发，还是还要做事件持久化、统计和多端同步。
- 不应在未定义数据所有权、权限和隐私规则前默认保存原始事件或视频。

## 已知旧协议线索

- VM33 旧协议证据位于 [`workspace/legacy-migration/evidence/VM33协议文档.md`](../legacy-migration/evidence/VM33协议文档.md)，其核心是 HTTP JSON 的 `Seq` / `Class` / `Method` / `Param` 模型。
- VM33 Pro 迁移计划要求新增业务通过 AXTP 新协议承接，不在旧 VM33 `Class.Method` 上原地扩展；旧设备和旧 App 的兼容路径保持独立。
- 当前未找到篮球投篮、进球或篮球检测开关的既有 legacy 命令、日志或已采纳 AXTP 事实。若设备固件已有私有实现，应补充其命令、状态和事件样例作为后续输入。
- 现有 AXTP 已定义 WebSocket JSON 的 RPC 与事件承载 profile，但篮球业务语义尚未进入 generated protocol；是否直接复用该 profile 由后续 flow / protocol 阶段确认。

## 可能的 AXTP 影响（仅供后续分析）

- 需要一个可被能力发现或版本判断的“篮球事件检测”可选能力。
- 需要一个用于读取/修改检测开关并反馈生效状态的控制交互。
- 需要一个或多个设备主动事件，用于表达投篮和进球；是否拆分为两个事件、是否包含关联 ID / 时间戳 / 置信度，待协议草案确认。
- 需要明确事件与 WebSocket 会话、授权、重连、顺序、去重和可靠性之间的边界。
- 用户指定的候选业务归属为 `sport.basketball`；当前 `sport` domain 尚未进入 AXTP registry，正式定域和 domain 注册仍需协议评审确认。
- 若后续确认现有能力或控制交互无法覆盖，应进入 `workspace/protocol/**` 的业务协议草案；若已有 adopted/generated 能力足够，则直接进入 App / SDK / 固件实现评估。

## 产品验收标准

1. 在支持该能力的 VM33PRO 上，App 能发现并展示篮球事件检测入口及当前有效开关状态。
2. 用户打开开关后，设备在规定的生效条件内进入检测状态；App 能显示实际生效结果，失败时不误显示为开启。
3. 在检测开启和场景满足条件时，设备能向已授权 App 推送投篮事件，App 能正确接收并展示/计数。
4. 对于设备判定为命中的投篮，App 能收到进球事件，并能将其与对应投篮按产品定义关联。
5. 用户关闭开关后，设备按照已确认的停止语义不再产生新的篮球事件；App 能显示关闭已生效。
6. WebSocket 断开、重连、设备重启或算法暂不可用时，App 能显示明确状态，并按确认的策略处理事件丢失、补发和重复。
7. 不支持该能力的设备不会出现可操作但必然失败的入口；控制失败、权限失败和参数错误可被测试复现并给出明确结果。
8. 事件时延、顺序、去重、持久化和隐私行为均有可执行的测试口径，并由产品、算法、固件、App 和测试共同签字确认。
