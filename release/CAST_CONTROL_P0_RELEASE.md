# Cast control P0/P1 release preparation

Current unpublished engineering contract: [control refresh](../specs/49-cast-control-refresh.md). Its Layout replacement is intentionally breaking within the development input; do not claim this is an additive published release. Formal release/version approval remains separate.

The locally adopted [optional WebCast backend feature](../specs/47-cast-webcast-backend.md)
adds a separate query/event/capability and independent cursor. It does not alter
P0 batches, P1 settings sequences or legacy backend contracts. Publication remains
a separate release-owner action; implementation checkpoints are not release tags.

Change baseline: `a2a550313bcf570361f1bfe9872851141b847520` (spec/v0.17.0).
Proposed target: next additive minor `spec/v0.18.0`, subject to release-owner
publication. No tag is created by this change. New business facts remain draft;
controlVersion=1 does not rename the protocol or runtime version.

The [contract](../specs/45-cast-control.md),
[registry](../contract/registry/domains/cast/domain.yaml) and
[P0 conformance profile](../conformance/profiles/cast-control.yaml) define P0.
The [settings contract](../specs/46-cast-settings.md) and
[combined conformance profile](../conformance/profiles/cast-settings.yaml) complete
P1 including C12 and PS-01–PS-12. Review source is revised r1 plus the detailed
settings plan, with local adoption decisions in workspace/business/cast-unified-control-r1.md and the four
feature proposals (workspace materials are intentionally omitted from artifacts).

Before publication run generator build/lint/test, validate, validate:sources,
generate, validate:protocol, conformance validation, generated drift, Markdown
links, protocol status and diff checks. Snapshot updates must use Vitest, never
manual edits. A local artifact dry run checks packaging, not release provenance
for an uncommitted worktree.

Downstream update order:

1. Publish an approved exact spec tag/commit and spec artifact after review.
2. cpp-runtime updates AXTP_SPEC.lock.yaml, regenerates its own IDs/types/codecs
   and validates decimal-string encoding and this profile. Never hand-edit its
   generated headers. Its release version is independent of the spec tag.
3. Axent updates its runtime dependency and exposes the public control surface
   without leaking cpp-runtime types into public headers.
4. NearCast updates Axent and implements the real owner/capture/dedup/cleanup
   boundaries. Queue defaults, layout/audio policy and physical media acceptance
   stay there. Old clients continue using the original single-source surface.

Local reference-model evidence does not certify downstream runtime behavior.
Publishing, hosted CI and the three downstream repositories are outside this task.

can declare a different restart partition; the NearCast fixture retains its three
restart-only keys. P1 settings/progress never enter P0 eventSequence. Real live
policy commits still emit P0 functional events; their versions are associated by
appliedControlRevision. Both snapshot barriers share one host capture boundary.

`codex/unified-cast-control` for downstream development and review; the exact
checkpoint is identified by its Git commit. No spec tag/release or downstream
implementation change is included. Target remains proposed spec/v0.18.0;
protocol metadata 1.0.0, wire version 1 and controlVersion=1 remain independent.
The three downstream repositories were not authorized for mutation by this task.

The pending integration work is cpp-runtime spec lock + generated IDs/DTOs/codecs
and independent conformance; then Axent dependency update/public asynchronous

store/owner, startup locking, policy application, dual-stream host projection and
UI/media acceptance. No receiver observation, automatic restart or stopped test
automation was resumed.
